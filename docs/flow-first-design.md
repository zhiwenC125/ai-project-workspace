## 信息层级

1. 跨项目空间：项目、共享资料及其依赖和引用。
2. 项目流程画布：需求、设计、开发、验收、发布等业务阶段。
3. 节点工作空间：阶段内的工作项、负责人、业务状态和自动化概况。
4. Harness 任务会话：围绕一个工作项进行完整对话、执行工具、检查产物。

个人助手入口保留。个人会话默认私有；项目会话具有明确的共享范围。本版没有重建已有的个人助手功能。

## 原型路径

- 从项目画布点击「开发实现」节点，进入节点选中状态。
- 右侧查看 7 个工作项、2 个已完成、2 个待评审以及当前执行摘要。
- 点击「进入节点工作空间」，查看节点范围内的看板。
- 点击 WS-128 卡片或「继续 WS-128 会话」，进入完整 Harness 任务会话。
- 会话左侧是任务上下文，中央为对话与执行，右侧为 PR 和验收信息。
- 使用「返回节点看板」「回到项目流程」回到相应层级。
- 从左侧「跨项目空间」进入关系画布，再点击当前项目返回项目流程。

61 个跨画板导航入口已配置。查看和导航都不触发任务运行。

## 业务对象与执行映射

ProjectNode 是长期业务对象，保存稳定 ID、验收条件、工作项关联、负责人与可视化位置。一个节点可绑定多个自动化定义，一个自动化定义可执行多次。

不要将 ProjectNode.id 与工作流 step ID 或 execution ID 混用。每次运行保存独立 WorkflowRunRef，再关联 Harness session、agent run、外部 PR 和产物。

定义版本与运行实例分开保存；修改流程不会改写历史运行使用的版本。业务进度由工作项与验收计算，不能使用最后一次工作流成功状态代替。

## 一致的演示数据

V2 示例项目共 12 个工作项、5 个已完成：需求 2/2，设计 1/1，开发 2/7，验收 0/1，发布 0/1。开发节点列数为待开始 1、进行中 2、待评审 2、已完成 2。与 v0.1 示例不同，以 `integration/project-flow.example.json` 为 V2 的场景定义。

WS-128 业务状态待评审，执行等待人工处理；WS-129 正在执行；WS-134 上次回写失败。失败恢复只针对已确认失败的步骤，远端写入结果未知时先核对结果。

## 自研工作流引擎与项目画布的关系

自有前端展示业务流程，自有业务服务持久化项目事实，自研引擎执行自动化运行。管理自动化时再进入工作流配置。一个业务节点不要求对应一个工作流步骤。

跨项目图中的依赖与引用默认不执行任何动作。自动执行需要明确的触发绑定、权限和输入。画布平移、排序、节点坐标改变不修改执行语义。
